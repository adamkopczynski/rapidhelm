# River venue dynamics

The version-2 venue in `content/venues/training-channel.json` is the canonical source for channel bounds, spawn, current ramp, waves, circular obstacles and elliptical flow regions. Zod validates content; Rust independently validates a staged update before replacing the active venue. Restart and boat tuning preserve the venue and return to its authored calm-pool spawn.

The initial pool has zero current, zero waves and a flat surface. Downstream current rises smoothly over the authored entrance ramp, slows near banks and is deflected around rocks using a local potential-flow approximation and a wake attenuation term. Elliptical regions blend smoothly into authored velocities with optional circulation. Their core can run upstream even when the main channel runs downstream. This is a deterministic authored velocity field, not real-time fluid dynamics.

Boat drag uses water-relative velocity. Bow/stern flow differences add rotational water drag and a local target yaw rate, so current shear can turn the hull. The water surface has a smoothly introduced slope plus deterministic travelling/cross waves. Analytical height gradients apply `-g * gradient` planar acceleration; rendering receives those same heights and gradients from Rust. Wave effects are therefore physical as well as visual. Heave, pitch and roll remain rendering responses to the sampled surface; this is not a full six-degree-of-freedom buoyancy model.

The 3.8 m kayak is an oriented capsule: radius 0.42 m and centerline half-length 1.48 m. Side/end walls constrain the full hull footprint. Rocks contact the closest point on the capsule centerline, with mass/inertia-aware normal impulses and 0.12 restitution. Updated motion is integrated in short pose increments (0.12 m travel target, capped at 4096 increments per fixed step) to avoid tunnelling at supported gameplay speeds. Contact correction iterates over the walls and obstacles. Native tests cover all headings at all four walls and a 1000 m/s rock approach; compiled-WASM tests inspect the authored venue over a long control sequence. The cap is a pathological-input work limit, not a guarantee for arbitrary injected velocities beyond the tested range.

ABI v3 adds staged venue setup, simulation time/contact counters and shared-memory water queries. One sample returns eight f64 values (VX, VZ, height, gradient-X, gradient-Z, wave amplitude, turbulence, depth). A batched grid returns row-major height/VX/VZ/gradient-X/gradient-Z as f32, up to 4096 points. The renderer borrows the grid until the next grid call, avoiding thousands of per-vertex WASM calls. Pure simulation tests can still run without a venue to isolate Sprint 1 handling.

Validation: native tests isolate downstream drift, reverse eddy drift, surface-gradient correctness, wave-dependent trajectories, rock-flow deflection, contact exclusion, calm spawn/reset and deterministic long runs. TypeScript tests execute the actual WASM, compare scalar/grid sampling, reject invalid venue staging atomically, and check the entire hull against all authored boundaries/rocks. E2E/Playwright tests are skipped by session instruction.
